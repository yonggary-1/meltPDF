# meltPDF v0.19.2

**수정: 수천 장을 불러오면 프로그램이 꺼지던 문제, 버그 리포트 위치/이름/크래시 알림.**

1. **수천 장에서 꺼짐** (새 파일 `visible_thumbs.py`, `tile_view.py`, `doc_model.py`, `drag_reorder.py`):
   - 무엇이 있었나: 사용자의 v0.19.1 충돌 기록에 따르면, 목록이 약 4,980장일 때(그랑블루 4,907장을 다 읽고 두 번째 폴더를 중간에 이어 넣던 중) 프로그램이 Tcl/Tk 내부 오류(0x80000003)로 스스로 멈췄습니다. 그때 화면 스레드는 캔버스에 썸네일을 올리던 중이었습니다. v0.19.0의 "불러오는 도중 끌어다 놓으니 크래시"도 같은 문제로 봅니다(끌어다 놓기 자체보다 목록 장수가 원인).
   - 왜: 이전에는 목록의 모든 항목마다 Tk 화면 그림을 만들어 캔버스에 올려 두었습니다. 6,000장 시험에서 화면 그림 6,005개, 메모리 808MB였습니다. 윈도우에서는 화면 그림마다 그래픽 자원(비트맵)을 따로 잡아서, 수천 개에서 한도에 닿아 Tk가 멈춘 것으로 판단했습니다.
   - 어떻게: 썸네일 그림은 화면에 보이는 타일과 위아래 한 화면 분량에만 만들고, 스크롤해서 벗어나면 지웁니다. 타일 테두리와 이름은 모든 타일에 그대로 있습니다. 썸네일 데이터(작은 PNG)는 항목에 늘 있어 다시 보일 때 바로 만듭니다. 드래그 중에는 유령 그림을 붙잡아 둡니다.
2. **버그 리포트 위치** (`bug_report.py`): v0.19.1은 보고서를 `%APPDATA%\meltPDF\logs`에 만들어 찾기 어려웠습니다. 이제 **`meltPDF.exe`가 있는 폴더**에 만듭니다. exe 폴더에 쓸 수 없을 때만(Program Files 등) `%APPDATA%` 쪽에 만들고 알림 창에 위치를 보여 줍니다. 활동 기록(`meltPDF_log.txt`)은 보고서의 재료라 그대로 `%APPDATA%`에 둡니다.
3. **보고서 이름** (사용자 지정 규칙): `프로그램명_버전_bug_report_yyyymmddHHMMSS.txt`. 프로그램명은 소문자, 버전은 점을 뺀 숫자입니다. 예: `meltpdf_0192_bug_report_20261014153012.txt`. 같은 초에 또 생기면 `_2`를 붙입니다.
4. **크래시 알림** (사용자 지정 문구): 갑자기 꺼진 다음 실행 때 "크래시 감지. [보고서 파일 이름]이 생성되었습니다."와 위치(폴더)를 보여 주고, 폴더를 열지 묻습니다.
5. **[설정]의 버튼**: [버그 리포트 폴더 열기]를 [버그 리포트 만들기]로 바꿨습니다. 오류 창이 없던 문제도 지금 상태 + 최근 기록 + 지난번 실행 기록으로 보고서를 exe 옆에 만듭니다. 오래된 보고서 정리(최근 20개)는 exe 폴더의 `meltpdf_*_bug_report_*.txt`만 대상으로 합니다.

**확인한 것:**
- 6,000장(리눅스, Wine의 윈도우용 파이썬): 동시에 살아 있는 화면 그림 최대 45개, Tk 그림 34~35개, 메모리 114MB(이전 808MB). 맨 위/가운데/맨 아래 스크롤, 목록형, 중간에 끌어다 놓기, 순서 바꾸기, 삭제, 전체 삭제 뒤에도 보이는 타일마다 그림이 있고 위치가 맞음.
- 불러오는 중 화면(썸네일이 보이고 [중단] 버튼), 썸네일 끌어서 순서 바꾸기, 밖에서 끌어 놓기, 기존 회귀 시험 통과.
- 보고서: 오류와 강제 충돌 뒤 exe 폴더에 새 이름으로 생김(Wine에서 PyInstaller로 만든 exe 포함). 다음 실행 때 "크래시 감지. ...이 생성되었습니다." + 위치. 쓸 수 없는 폴더일 때 %APPDATA% 쪽으로. [버그 리포트 만들기]. 같은 초 겹침.

**확인하지 못한 것:**
- 실제 윈도우에서 같은 폴더(그랑블루 + 두 번째 폴더)로 다시 꺼지지 않는지. 윈도우 그래픽 자원 한도는 Wine에서 재현되지 않아 충돌 자체는 이 환경에서 재현하지 못했습니다.
- 빠르게 스크롤할 때 썸네일이 늦게 나타나 보이는지.

### 받는 방법
이 릴리스의 소스는 위 태그(`v0.19.2`)의 소스 코드입니다. 압축을 풀고 폴더 구조를 그대로 둔 채 `build.bat`을 더블클릭하면 `dist\meltPDF.exe`가 만들어집니다(Python 3.9 이상 필요, 인터넷 필요). 자세한 사용법은 README.md, 전체 변경 이력은 CHANGELOG.md, 외부 소프트웨어 출처는 THIRD_PARTY_NOTICES.md를 보세요.
