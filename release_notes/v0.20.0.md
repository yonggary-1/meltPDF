# meltPDF v0.20.0

**기능: PDF 저장 창이 원본 옆에서 "원본이름_Reprint.pdf"로 열림 (사용자 요청).**

1. **저장 창의 처음 위치와 기본 이름** (새 파일 `pdf_save_name.py`, `doc_model.source_paths`):
   - 파일 하나 또는 폴더 하나만 불러왔으면 저장 창이 그 파일/폴더가 있는 폴더에서 열리고, 기본 이름은 "원본이름_Reprint.pdf"입니다(파일은 확장자를 뺀 이름, 폴더는 폴더 이름).
   - 예: `D:\책\book.epub` -> `D:\책`에서 `book_Reprint.pdf`, `D:\사진\여행` 폴더 -> `D:\사진`에서 `여행_Reprint.pdf`. 원본이 PDF여도 이름이 달라 원본을 덮어쓰지 않습니다.
   - 여러 개를 불러왔으면 예전처럼 처음 불러온 것의 이름.pdf이고, 위치는 윈도우가 정합니다(보통 마지막으로 저장한 곳).
   - 같은 파일을 두 번 넣으면 하나로 셉니다. 목록을 모두 지우면 처음부터 다시 셉니다. 원본 폴더가 없어졌으면 이름만 제안하고 위치는 윈도우에 맡깁니다.

**확인한 것** (리눅스, Wine의 윈도우용 파이썬):
- 단위 시험: 빈 목록, 폴더 하나, 파일 하나, 같은 파일 두 번, 파일 둘, 사라진 폴더, 전체 삭제 후 다시 - 모두 기대한 위치와 이름.
- 앱을 띄워 실제로 불러온 뒤 [PDF 내보내기]를 눌러 저장 창에 넘어가는 값 확인: 폴더 하나(`book_Reprint.pdf`, 원본 폴더의 상위), cbz 하나(`만화_Reprint.pdf`), 이미지 하나(`b_Reprint.pdf`), 이미지 둘(`b.pdf`, 위치 지정 안 함), 폴더+cbz(`book.pdf`, 위치 지정 안 함). Wine에서는 한글 이름 폴더/cbz(`여행_Reprint.pdf`, `만화_Reprint.pdf`)와 윈도우 경로(`Z:\\...`)로 같은 결과.

**확인하지 못한 것:**
- 실제 윈도우 저장 창이 그 위치에서 열리는지(한글 경로, 네트워크 드라이브 포함).
