# meltPDF v0.10.0

**[이미지 내보내기] 기능을 추가했습니다. 목록의 이미지를 파일로 풀어 주고, 압축 파일 안의 하위 폴더는 한 폴더에 펼치며, 이름이 겹치면 번호를 붙입니다.** 이름 처리를 공용 파일(`name_codec.py`)로 모았고, 프로젝트 라이선스를 AGPL-3.0 이상으로 정했습니다.

1. **이미지 내보내기** (새 파일 `image_export.py`, `image_export_dialog.py`, `app_window.py`에 버튼 한 줄): 하단 바의 [PDF로 내보내기] 옆에 [이미지 내보내기] 버튼이 생겼습니다. 누르면 팝업이 열리고 세 버튼이 있습니다.
   - **[원본 파일 위치에 폴더 생성 후 풀기]**: 처음 불러온 파일이 있는 폴더 안에 만듭니다(폴더를 끌어다 넣었으면 그 폴더가 들어 있는 폴더).
   - **[설정 폴더에 폴더 생성 후 풀기]**: 설정 창의 "이미지 내보내기 기본 폴더"(새 항목, 찾아보기 버튼 포함) 안에 만듭니다. 지정이 없거나 폴더가 없으면 지정하라는 안내만 보입니다.
   - **[찾아보기...]**: 폴더 선택 창에서 고른 폴더 안에 만듭니다.
   - 새 폴더 이름은 처음 불러온 파일 이름(확장자 제외)이고, 이미 있으면 덮어쓰지 않고 `이름 (1)`, `이름 (2)`로 만듭니다.
   - **압축 파일 안의 하위 폴더는 만들지 않고 한 폴더에 펼칩니다.** 이름이 겹치면(대소문자 무시) `001 (1).jpg`처럼 확장자 앞에 번호를 붙이고, 손상된 이미지 안내와 같은 정보 창으로 "어떤 이름이 어떻게 바뀌었는지"를 먼저 알립니다. 세 개 이상 겹치면 (2), (3)으로 이어집니다. 목록 순서에서 먼저 나온 것이 원래 이름을 가집니다.
   - 파일 이름은 목록에 보이는 이름("파일명 변경하기" 결과 포함)에서 폴더 부분을 뗀 것입니다. 윈도우가 허용하지 않는 글자는 `_`로 바꾸고(끝의 점/공백 제거, `CON` 같은 예약 이름 앞에 `_`, 너무 긴 이름 줄임), 일본어/중국어/한국어 글자는 그대로 둡니다.
   - 원본 바이트를 그대로 저장합니다(재인코딩 없음). 단 EXIF 회전을 반영해 목록에 담은 이미지와 손상되어 일부만 읽은 이미지는 목록에 들어 있는 PNG가 저장되므로 확장자가 `.png`가 됩니다. 확장자는 파일 앞부분을 보고 정해서, 확장자와 내용이 다르면 내용에 맞춥니다.
   - PDF에서 가져온 페이지는 이미지 파일이 아니므로 저장하지 않고, 완료 창에 몇 개를 건너뛰었는지 알립니다. 저장은 백그라운드로 하며 상태 표시줄에 진행이 나오고, 일부 파일을 못 쓰면 경고 창에 목록이 나옵니다.
2. **이름 처리 공용화** (새 파일 `name_codec.py`): zip 이름 복원, 윈도우용 이름 정리, 겹치는 이름/폴더 번호 붙이기를 한 파일로 모았습니다. `archive_zip.py`와 `rename_pages.py`(이름 일괄 변경의 금지 글자 처리)가 이 파일을 씁니다.
   - **zip 이름 복원 방식 변경:** 이전에는 파일 하나씩 cp949를 먼저 시도해서, 옛 일본어/중국어 zip 이름이 한글로 깨졌습니다. 이제 압축 파일 전체의 이름들을 보고 UTF-8, cp949, cp932(일본어), gbk(간체), big5(번체) 중 가장 그럴듯한 인코딩 하나를 고릅니다(UTF-8 표시가 있는 항목은 그대로).
   - **한계:** 한자만으로 된 짧은 이름은 일본어/중국어/한국어를 바이트로 구별할 수 없어 한국어(cp949)를 우선합니다. 가나나 한글이 섞이면 거의 정확합니다.
3. **원본 폴더 기억** (`doc_model.py`, `file_loader.py`, `book_loader.py`): "처음 불러온 파일"의 이름과 함께 그 파일이 있는 폴더도 기억합니다(목록이 비면 함께 지워짐).
4. **라이선스를 AGPL-3.0 이상으로 정했습니다.** 배포하는 exe에 PyMuPDF(AGPL-3.0 또는 Artifex 상용 이중 라이선스)가 들어가기 때문입니다. 설치된 패키지 정보에서 확인한 구성요소별 라이선스와 근거는 `THIRD_PARTY_NOTICES.md`, 요약은 README의 "라이선스"에 적었습니다. exe를 남에게 배포할 때는 소스 저장소 위치를 함께 알려야 합니다.
5. 문서: ROADMAP에서 Shift 범위 선택은 하지 않기로, Ctrl+A는 그대로 두기로 정리했고(Delete 키는 이미 동작), RAR를 메모리로 받는 방안(`unrar p`)과 남은 한계를 적었습니다.

**확인한 것:** 가상 화면(Xvfb)에서 실제로 시험했습니다.
- 이름 복원: 한국어/일본어(가나 포함·한자만)/중국어 간체/번체/UTF-8 표시 있는 zip/ASCII 샘플 13종이 모두 맞음. 무작위로 만든 이름(글자 1~6개)으로 측정한 정확도(합성 이름 기준이며 실제 파일 이름 분포와 다를 수 있음): 한 파일만 든 zip은 한국어 398/400, 일본어 400/400, 중국어 간체 266/400, 번체 311/400. 이름이 5개 든 zip은 한국어/일본어 모두 400/400, 간체 390/400, 번체 400/400. 한 파일뿐인 짧은 중국어 이름은 틀릴 수 있습니다.
- 이미지 내보내기(화면 시험): 일본어(cp932, UTF-8 표시 없음) 이름의 zip을 끌어다 넣어 이름이 복원되고, 하위 폴더 두 곳에 같은 이름이 있는 7장이 한 폴더에 펼쳐지며, 겹친 3개(`001 (1).jpg`, `002 (1).png`, `表紙 (1).png`)가 안내창과 함께 번호가 붙고, 저장된 파일 내용이 원본 바이트와 같음. 원본 위치/설정 폴더/찾아보기 세 경로, 폴더 이름 중복 `(1)`, 설정 폴더 미지정 안내, PDF 페이지 건너뜀 안내, 팝업과 설정 창 모양(스크린샷) 확인.
- 단위 시험: EXIF 회전 이미지가 `.png`로, 확장자 없는 이름에 확장자 보충, 금지 글자/예약 이름 정리, 대소문자만 다른 이름 겹침, 디스크 원본 복사, 중국어/한국어 이름 유지, 손상 이미지가 `.png`로 저장됨.
- 회귀: zip 자연 정렬/UTF-8 이름/cp949 이름, 이름 변경 접두사 정리, 예전 설정 파일(새 항목 없음) 읽기와 잘못된 값 무시, 원본 폴더 기억과 지움.
- 원본 폴더 기억: 폴더를 끌어다 놓으면 그 폴더가 들어 있는 폴더가, 이미지 파일을 놓으면 그 파일이 있는 폴더가 "원본 파일 위치"로 기록됨(실제 끌어다 놓기 흐름으로 확인).
- 라이선스: 설치된 패키지의 메타데이터와 PyInstaller 공식 `COPYING.txt`로 확인.

**확인하지 못한 것:**
- 진짜 Windows 화면(폴더 선택 창, 팝업 배치)과 Windows 탐색기에서의 결과 폴더.
- 이번 작업 중 작업 환경이 초기화되어 이전 시험 자료(손상된 rar/zip 샘플, 이미지 보기/키 이동 시험)가 사라졌고, 그 시험들은 변경 후에 다시 돌리지 못했습니다. 이번에 건드린 것은 zip 이름 복원, 원본 폴더 기억, 이름 변경 접두사, 설정뿐이고 rar/손상 이미지/이미지 보기 코드는 바꾸지 않았지만, 변경 후 전체 재시험은 하지 못했습니다.
- 공식 AGPL 전문(`LICENSE` 파일): 이 환경에서 원문 사이트에 접속할 수 없어 받지 못했고 임의로 작성하지 않았습니다. GitHub 저장소에서 "Add file → Create new file → `LICENSE` → Choose a license template → GNU AGPLv3"로 추가해야 합니다. 법률 자문이 아닙니다.
- 매우 큰 이미지 수천 장을 내보낼 때의 속도, 윈도우의 긴 경로(260자 이상) 처리.

### 받는 방법
이 릴리스의 소스는 위 태그(`v0.10.0`)의 소스 코드입니다. 압축을 풀고 폴더 구조를 그대로 둔 채 `build.bat`을 더블클릭하면 `dist\meltPDF.exe`가 만들어집니다(Python 3.9 이상 필요, 인터넷 필요). 자세한 사용법은 README.md, 전체 변경 이력은 CHANGELOG.md, 외부 소프트웨어 출처는 THIRD_PARTY_NOTICES.md를 보세요.
