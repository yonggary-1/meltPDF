# meltPDF v0.11.0

**새 기능: epub와 fb2에서 이미지 꺼내기.** 책 안의 이미지만 책에 나오는 순서대로 목록에 넣습니다.

1. **EPUB 읽기** (새 파일 `book_epub.py`): epub의 `content.opf`에 적힌 쪽 순서(spine)대로 각 쪽(xhtml)의 `<img>`와 `<svg><image>`를 만나는 순서로 이미지를 모읍니다. zip처럼 이름 순으로 정렬하지 않는 이유는, epub 안의 파일 이름은 책 순서와 무관한 경우가 많기 때문입니다. 같은 이미지가 여러 쪽에서 쓰이면 처음 자리에만 넣고, 표지(cover-image)로 지정된 이미지는 쪽에서 쓰지 않아도 맨 앞에 넣습니다. 쪽 안의 주소(`../images/a b.png`, `%20`로 인코딩된 이름, 한글 이름)는 풀어서 찾고, 바깥 주소(http)와 `data:`는 건너뜁니다. `container.xml`이 잘못된 책은 첫 `.opf`를 씁니다. 이미지가 없는 글 위주 epub은 "이미지가 들어 있지 않습니다"로 나옵니다.
2. **FB2 읽기** (새 파일 `book_fb2.py`): fb2는 XML 파일 하나이고 이미지는 끝의 `<binary>`에 base64로 들어 있습니다. 문서에 `<image>`가 나오는 순서(표지 -> 본문)로 이미지를 모읍니다. 큰 파일도 버티도록 XML을 조금씩 읽으며 이미지를 바로 풉니다. `.fb2.zip`(zip 안에 fb2 하나)도 열립니다. 이름은 이미지 id에 내용에 맞는 확장자를 붙인 것입니다. 본문에서 쓰지 않는 이미지는 빼고, 쓰는 것이 하나도 없을 때만 파일에 든 순서로 넣습니다.
3. **파일 종류는 내용으로 판별합니다** (`book_import.py`): 이전에는 `.epub`이 지원 목록에 없어 열 수 없었고, 이름을 `.zip`으로 바꿔 열면 이름 순으로 섞였습니다. 이제 zip 안에 `META-INF/container.xml`이 있으면 epub, `.fb2`가 하나뿐이면 fb2.zip, 파일 앞부분이 `<FictionBook`이면 fb2로 읽습니다. 파일 선택 창과 끌어다 놓기에 `.epub`, `.fb2`가 추가되었습니다. 그 밖의 zip/cbz/rar는 이전과 같습니다.
4. **안전장치:** DRM(저작권 보호)으로 암호화된 이미지/쪽이 있는 epub은 열지 않고 사유를 알립니다(우회하지 않음). 글꼴만 가리는 난독화는 DRM이 아니라 무시합니다. XML에 엔티티 선언(DOCTYPE 안의 ENTITY)이 있으면 확장 공격 위험이 있어 거절합니다. 항목 하나 1GB, 전체 16GB 한도는 zip과 같습니다. 이미지가 중간에서 깨진 epub은 읽힌 부분만 불러오고 빨간 테두리로 표시합니다(zip과 같은 방식). 새 외부 패키지는 쓰지 않았습니다(파이썬 기본 라이브러리만).

**확인한 것:** Linux 가상 화면(Xvfb)에서, 직접 만든 시험 파일로 확인했습니다.
- epub: 이름 순과 읽기 순서가 다른 책에서 읽기 순서대로 나옴, 표지가 맨 앞, 중복 이미지는 한 번만, `../` 경로·공백이 `%20`인 이름·한글 이름, 바깥 주소와 `data:` 무시, `<img>`가 닫히지 않은 xhtml(`&nbsp;`가 있는 DOCTYPE 포함), 꺼낸 이미지가 원본과 바이트까지 같음(메모리/디스크 방식 모두), 글꼴 난독화만 있는 책은 열림, 이미지가 암호화된 책은 DRM 안내로 거절, 글 위주 책은 "이미지가 들어 있지 않습니다", `container.xml`이 틀린 책은 첫 `.opf`로 읽음, 엔티티 폭탄 거절, `.zip` 이름의 epub도 epub로 판별, 한 바이트를 바꾼 이미지는 손상 표시.
- fb2: 표지 -> 본문 순서, 같은 이미지 중복 한 번만, 글꼴 등 이미지 아닌 binary 무시, 확장자 없는 id에 내용에 맞는 확장자, 이름의 확장자가 내용과 다르면 내용에 맞춤, 본문에서 쓰는데 없는 이미지는 경고, windows-1251 인코딩 파일, 네임스페이스가 없는 `href`, 본문에서 쓰는 이미지가 없으면 binary 순서, `.fb2.zip`, 엔티티 선언 거절, 잘린 파일은 오류 안내. 이미지 120장(합계 114MB, 파일 154MB) 1.4초에 읽었고 메모리 최고치는 시작 시점(62MB)보다 120MB 늘어난 182MB.
- 화면: 끌어다 놓기로 epub(5장), fb2(3장 + 없는 이미지 경고)를 차례로 넣으면 한 목록에 순서대로 쌓이고, 글 위주 epub과 DRM epub은 각각 경고 창으로 사유가 나옴. epub으로 만든 목록을 PDF로 내보내면 페이지 크기가 이미지 크기와 같음.
- 회귀: zip(이름 순 유지)/이름 복원/이미지 내보내기/잘린 zip 복구/RAR 직접 받기 시험이 모두 그대로 통과.

**확인하지 못한 것:**
- **실제 epub/fb2 파일:** 이 환경에는 진짜 책 파일이 없고 외부에서 내려받을 수도 없어, 직접 만든 시험 파일로만 확인했습니다. 실제 책에서는 만든 도구마다 구조가 달라(고정 레이아웃, CSS 배경 이미지로 쪽을 그리는 책, 이미지를 `<object>`로 넣는 책 등) 순서가 이상하거나 이미지가 빠질 수 있습니다. CSS 배경 이미지와 `<object>`는 아직 읽지 않습니다.
- **Windows:** 파일 선택 창의 필터와 윈도우 경로는 확인하지 못했습니다.
- DRM 판정은 `encryption.xml`의 암호화 방식 기준입니다. 이 환경에서는 DRM이 걸린 실제 책이 없어 직접 만든 암호화 표시로만 시험했습니다.
- mobi/azw/azw3, djvu, pdf 이미지 꺼내기는 이번 빌드에 없습니다(ROADMAP 순서: pdf -> mobi 계열 -> djvu).
- fb2의 `<binary>`가 서로 다른 id로 같은 내용인 경우는 중복으로 보지 않습니다.

### 받는 방법
이 릴리스의 소스는 위 태그(`v0.11.0`)의 소스 코드입니다. 압축을 풀고 폴더 구조를 그대로 둔 채 `build.bat`을 더블클릭하면 `dist\meltPDF.exe`가 만들어집니다(Python 3.9 이상 필요, 인터넷 필요). 자세한 사용법은 README.md, 전체 변경 이력은 CHANGELOG.md, 외부 소프트웨어 출처는 THIRD_PARTY_NOTICES.md를 보세요.
