# meltPDF v0.9.0

**썸네일을 두 번 누르면 원본 크기의 이미지를 팝업 창으로 볼 수 있습니다** (축소/맞춤/확대 버튼, 확대하면 끌어서 이동).

1. **이미지 보기 창** (새 파일 `image_viewer.py`, `app_window.py`에 한 줄 연결): 타일형/목록형 모두에서 썸네일을 두 번 누르거나, 선택한 항목에서 Enter를 누르면 창이 열립니다. 한 번 누르는 것은 선택과 끌어서 순서 바꾸기에 그대로 쓰므로 두 번 누름으로 정했습니다(누른 자리와 뗀 자리가 거의 같고 0.45초 안의 두 번째 누름만 인정하므로, 끌 때는 열리지 않습니다).
   - 창 아래의 세 버튼: **`-` 축소, `=` 창에 맞춤, `+` 확대**. 창을 열면 맞춤으로 시작하고, 맞춤 상태에서는 창 크기를 바꿔도 계속 맞춰집니다. 작은 이미지도 `=`를 누르면 창에 맞춰 커집니다.
   - 창보다 크게 확대하면 마우스로 끌어서 옮겨 볼 수 있습니다(가장자리 밖으로는 넘어가지 않음, 이때 커서 모양이 바뀜).
   - 덤으로: 마우스 휠은 가리킨 곳을 기준으로 확대/축소, 키보드 `+`/`-`/`=`, `Esc`는 닫기. 확대 비율(%)이 버튼 옆에 표시됩니다.
   - 열리는 것은 썸네일이 아니라 실제 크기의 이미지입니다. 기존 PDF 페이지는 긴 변 약 2600px로 그려서 보여줍니다(보기 전용, 내보내기와 무관). 손상된 이미지도 읽히는 부분까지 열리고 창 제목에 "손상됨" 표시가 붙습니다.
   - 화면에 보이는 부분만 잘라서 크기를 바꿔 그리므로 아주 큰 이미지를 크게 확대해도 메모리/속도 문제가 없습니다. 창은 하나만 쓰며, 다른 썸네일을 열면 그 창의 이미지가 바뀝니다. 이 기능은 목록을 바꾸지 않습니다.
2. **`damaged_image.py` 정리:** 손상된 이미지를 읽을 수 있는 부분까지 PIL 이미지로 여는 `open_tolerant()`를 따로 빼서, 목록에 넣을 때와 이미지 보기 창이 같이 씁니다(동작 변화 없음).

**확인한 것:** 가상 화면에서 실제 마우스 이벤트(xdotool)로 시험했습니다. (a) 한 번 누름은 열리지 않고 두 번 누름은 열림, (b) 맞춤 비율이 창에 정확히 맞고 확대 전에는 끌기가 비활성, (c) `+`/`-`가 1.25배씩 바뀌고 `=`로 되돌아옴, (d) 확대 상태에서 끌면 끈 만큼 이동하고 가장자리에서 멈추며 오른쪽 아래 모서리가 올바르게 그려짐(화면 확인), (e) 휠 확대에서 가리킨 점이 고정됨, (f) 창 크기를 바꿔도 맞춤 유지, (g) 작은 이미지와 기존 PDF 페이지가 열림, (h) 선택 후 Enter로 열리고 Esc로 닫힘, (i) 썸네일을 끌어서 순서를 바꿀 때는 창이 열리지 않고 순서 바꾸기가 그대로 됨. 기존 전체 테스트도 통과했습니다.
**확인하지 못한 것:** 진짜 Windows 화면과 Windows에서의 마우스 휠 동작(이벤트 값이 다릅니다. 코드에서 Windows/리눅스 둘 다 처리하게 했지만 Windows에서는 시험하지 못했습니다). 아주 큰 이미지(수천만 화소)를 열 때의 체감 속도는 이 환경에서만 확인했습니다.

### 받는 방법
이 릴리스의 소스는 위 태그(`v0.9.0`)의 소스 코드입니다. 압축을 풀고 폴더 구조를 그대로 둔 채 `build.bat`을 더블클릭하면 `dist\meltPDF.exe`가 만들어집니다(Python 3.9 이상 필요, 인터넷 필요). 자세한 사용법은 README.md, 전체 변경 이력은 CHANGELOG.md, 외부 소프트웨어 출처는 THIRD_PARTY_NOTICES.md를 보세요.
