# meltPDF v0.8.2

**손상된 이미지를 오류가 아니라 "손상된 이미지 N개가 있습니다" 안내로 알리고, 폴더/이미지를 직접 추가할 때도 손상된 이미지를 읽히는 부분만 불러오게 했습니다.** (v0.8.1을 써 보니 두 가지가 어색했습니다: 압축 파일 안의 손상 이미지가 "일부를 불러오지 못했습니다 ... 종료 코드 3" 같은 오류 창으로 나왔고, 압축을 풀어 둔 폴더를 끌어다 놓으면 손상된 이미지가 `broken data stream when reading image file` 오류와 함께 목록에서 빠졌습니다.)

1. **안내 방식 변경** (새 파일 `load_report.py`, `book_loader.py`): 손상된 이미지는 읽을 수 있는 부분만 목록에 넣는 정상 동작이므로, 경고 아이콘의 오류 창 대신 정보 창으로 "손상된 이미지 N개가 있습니다 (압축 파일 이름). 읽을 수 있는 부분만 표시하며, 빨간 테두리로 구분됩니다." 와 파일 이름 목록을 보여줍니다(20개까지, 넘으면 "외 N건"). 압축 도구의 종료 코드 같은 내부 문구는 사용자에게 보이지 않습니다. 목록에 넣지 못한 파일이 있을 때만 "일부를 불러오지 못했습니다" 경고가 나오고, 둘 다 있으면 한 창에 차례로 나옵니다.
2. **폴더/이미지 직접 추가에서도 손상된 이미지 처리** (`file_loader.py`): 이전에는 압축 파일에서 꺼낸 이미지에만 손상 처리가 있었고, 폴더/이미지 파일을 직접 추가하는 경로에서는 읽기 오류가 나면 그 파일이 그냥 빠졌습니다. 이제 이 경로에서도 읽히는 부분만 불러와 빨간 테두리로 표시하고 같은 안내를 합니다.
3. **읽지 못한 이미지의 설명을 한국어로** (`damaged_image.py`): 파일 맨 앞이 깨져 이미지로 인식되지 않는 파일은 여전히 목록에 넣을 수 없습니다. 이때 Pillow의 영어 오류 문구 대신 "손상되어 읽지 못했습니다(이미지 머리 부분이 깨졌거나 이미지 파일이 아닙니다). 목록에서 뺐습니다."를 보여줍니다.
4. **zip/cbz도 같은 안내 방식으로 통일** (`archive_zip.py`): 손상된 항목은 정보 창으로 알리고, 읽을 수 없어 뺀 항목만 경고로 알립니다. rar에서 도구의 종료 코드를 안내문에 넣던 것도 뺐습니다(`archive_rar.py`; 진단용 실패 이유는 압축 풀기가 완전히 실패했을 때만 보입니다).

**확인한 것:** (a) 화면에서 폴더를 끌어다 놓는 상황을 직접 시험했습니다. 정상 이미지 2장, 잘린 JPEG 1장, 머리가 깨진 파일 1장이 든 폴더에서 잘린 JPEG는 빨간 테두리로 들어오고, 머리가 깨진 파일은 한국어 설명과 함께 빠지며, 안내 창에 영어 오류 문구는 없습니다. (b) 손상된 rar 샘플은 오류 창이 아니라 정보 창이 뜨고 "종료 코드" 문구가 없는 것, 정상 rar는 아무 창도 뜨지 않는 것을 확인했습니다. (c) 손상된 zip(저장/압축 방식 모두)도 같은 결과입니다. (d) 기존 전체 테스트(분리 스모크, 드래그 막대, zip, 메모리/디스크, 키보드 이동, 툴바 줄바꿈, rar 읽기/앱 흐름 등)도 통과했습니다.
**확인하지 못한 것:** 진짜 Windows 화면과 사용자의 실제 문제 파일로는 확인하지 못했습니다. JPEG의 중간이 깨졌지만 Pillow가 오류 없이 읽어 내는 경우는 압축 파일 밖(폴더에서 직접 추가)에서는 손상으로 알아낼 수 없어서 빨간 테두리가 붙지 않습니다(압축 파일 안에서는 체크섬으로 가립니다).

### 받는 방법
이 릴리스의 소스는 위 태그(`v0.8.2`)의 소스 코드입니다. 압축을 풀고 폴더 구조를 그대로 둔 채 `build.bat`을 더블클릭하면 `dist\meltPDF.exe`가 만들어집니다(Python 3.9 이상 필요, 인터넷 필요). 자세한 사용법은 README.md, 전체 변경 이력은 CHANGELOG.md, 외부 소프트웨어 출처는 THIRD_PARTY_NOTICES.md를 보세요.
