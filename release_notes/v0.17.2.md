# meltPDF v0.17.2

**수정: 끌어다 놓은 폴더의 하위 폴더 처리, 불러오는 중 표시.**

1. **끌어다 놓은 폴더** (`file_loader._handle_dropped_folder`, 새 파일 `folder_ask.py`): 폴더 바로 안에 이미지가 없고 하위 폴더에만 있으면 아무 반응이 없던 문제(사용자 보고)를 고쳤습니다. 네 경우로 나눕니다.
   - 이미지도 하위 폴더도 없음: 아무것도 하지 않음.
   - 이미지만 있음: 묻지 않고 바로 불러옴.
   - 이미지 없이 하위 폴더만 있음: "이미지가 없습니다. 서브 폴더를 검색할까요?" [검색]/[취소]. 검색했는데 하위 폴더에도 없으면 "서브 폴더에서도 이미지 파일을 찾지 못했습니다." 안내.
   - 이미지와 하위 폴더 모두: "이미지가 X장 있습니다. 서브 폴더를 검색할까요?" [검색](하위 폴더까지 모두)/[확인](바로 안의 X장만).
   - 창을 닫거나 Esc는 아무것도 넣지 않음. 숨김 폴더와 `__MACOSX`는 하위 폴더로 치지 않음. 여러 개를 놓으면 놓은 순서대로 묻고 그 순서대로 들어감. 하위 폴더에서 넣은 이미지의 목록 이름은 "하위폴더/파일".
   - 이미지가 없는 폴더를 놓았을 때 그 폴더 이름이 기본 PDF 이름으로 잡히던 것도 고쳤습니다(실제로 불러올 때만 잡음).
2. **불러오는 중 표시** (`empty_hint.py`, `load_queue.py`): 큰 폴더를 불러오는 동안 하단 문구 말고는 변화가 없던 문제(사용자 보고). 목록이 빈 동안 불러오기 작업이 진행 중이면 가운데 안내 대신 "이미지 불러오는 중..."을 보여 줍니다. 하단 상태 줄에는 "이미지 불러오는 중... 120/3000"처럼 진행 수를 10장마다 갱신합니다.
3. **폴더 안 이미지 찾기를 백그라운드로**: 하위 폴더가 많으면 이미지 찾기 자체가 오래 걸려 화면이 멈출 수 있어, 찾기부터 일꾼 스레드에서 합니다([폴더 (이미지) 추가]도 같음).

**확인한 것:** Linux 가상 화면(Xvfb)에서 확인했습니다.
- 네 경우: 숨김 폴더만 있는 빈 폴더(반응 없음, 기본 이름도 안 잡힘), 이미지만 있는 폴더(묻지 않고 1-2-10 순서), 하위 폴더만 있는 폴더(취소하면 아무것도, 검색하면 "s1/1.png, s2/1.png, s2/deep/2.png"), 이미지 2장 + 하위 폴더(확인하면 2장만, 검색하면 3장), 하위 폴더에도 이미지가 없는 폴더(안내). 이미지 파일 + 폴더 + 이미지 파일을 함께 놓으면 그 순서대로 들어감. 묻는 창의 문구와 버튼([검색]/[취소], [검색]/[확인]).
- 불러오는 중: 작업이 진행되는 동안 가운데에 "이미지 불러오는 중...", 끝나면 원래 안내로 돌아감.
- Wine에서 윈도우용 파이썬으로 프로그램 전체 실행(djvu/7z/tar 불러오기, 서지 정보, 이미지 복사) 정상. 회귀 시험 모두 통과.

**확인하지 못한 것:**
- 진짜 Windows에서 묻는 창의 모양과, 아주 큰 폴더(수천 장)에서의 체감 속도. 읽는 속도 자체를 높이는 작업(JPEG 축소 풀기, 여러 장 동시 처리, 읽는 대로 바로 표시)은 다음 버전 예정입니다(ROADMAP).

### 받는 방법
이 릴리스의 소스는 위 태그(`v0.17.2`)의 소스 코드입니다. 압축을 풀고 폴더 구조를 그대로 둔 채 `build.bat`을 더블클릭하면 `dist\meltPDF.exe`가 만들어집니다(Python 3.9 이상 필요, 인터넷 필요). 자세한 사용법은 README.md, 전체 변경 이력은 CHANGELOG.md, 외부 소프트웨어 출처는 THIRD_PARTY_NOTICES.md를 보세요.
