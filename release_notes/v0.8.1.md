# meltPDF v0.8.1

**압축 파일 안에 손상된 파일이 있어도 열리게 하고, 손상된 이미지는 읽히는 부분만 불러와 빨간 테두리로 표시합니다. rar가 열리지 않을 때 원인이 화면에 나오도록 했습니다.** (v0.8.0에서 한 rar 파일이 "tar.exe: Error opening archive"로 열리지 않았고, 그 압축 파일 안에는 깨진 파일이 있었습니다.)

1. **손상된 파일이 하나라도 있으면 압축 파일 전체가 실패하던 문제 수정** (`rar_tool.py`): UnRAR는 압축 파일 안에 깨진 파일이 있으면 나머지를 다 풀고도 종료 코드 3("체크섬 오류")을 냅니다. 이전 코드는 0이 아닌 종료 코드를 모두 실패로 보고 결과를 버린 뒤 다음 도구(윈도우 `tar.exe`)로 넘어갔고, `tar.exe`는 한국어 문자 코드(cp949)에 없는 글자(`雑`, `号` 등)가 든 경로를 열지 못해 화면의 오류만 남았습니다. 이제 UnRAR 종료 코드 1(경고)/3(손상 파일)이거나 7-Zip 종료 코드 1이면서 풀린 파일이 하나라도 있으면 그 결과를 사용합니다. **이것이 사용자의 그 파일이 열리지 않은 실제 원인인지는 그 파일로 확인하지 못했습니다**(같은 종류의 손상 파일 샘플로 재현해 고쳤습니다).
2. **깨진 파일을 지우지 않고 읽히는 데까지 남김** (`rar_tool.py`, `archive_rar.py`): UnRAR에 `-kb` 옵션을 줘서 깨진 파일도 풀린 데까지 남깁니다. 어떤 파일이 깨졌는지는 압축 파일에 적힌 CRC32와 풀린 내용을 비교해서 가립니다(이름이나 글자 인코딩과 무관). 안내 창에 "손상된 이미지 N개: 이름 (읽을 수 있는 부분만 표시합니다)"가 나옵니다.
3. **zip/cbz도 같은 문제 수정** (`archive_zip.py`): 이전에는 항목 하나의 CRC가 틀리거나 압축 데이터가 중간에서 깨져 있으면 파일 전체가 "'이름'을(를) 읽지 못했습니다"로 열리지 않았습니다. 이제 읽힌 데까지 사용하고 손상으로 표시하며, 아예 읽을 수 없는 항목만 빼고 이름을 알려 줍니다. zip 항목의 CRC는 `zipfile`이 틀리면 마지막 덩어리를 버리고 예외를 내므로, 확인을 직접 하도록 바꿨습니다.
4. **손상된 이미지를 읽히는 부분만이라도 불러오기** (새 파일 `damaged_image.py`, `book_loader.py`): 잘리거나 일부가 깨져 평소처럼 읽으면 오류가 나던 이미지를, 읽을 수 있는 데까지 디코딩해 무손실 PNG로 담아 목록에 넣습니다. 목록에 보이는 모습과 PDF로 내보낸 모습이 같습니다(깨진 PNG를 원본 그대로 넣으면 PDF 변환이 실패해서 PNG로 담습니다). 파일 맨 앞이 깨져 이미지로 인식되지 않는 것은 읽을 수 없으므로 목록에서 빼고 이름을 알립니다.
5. **빨간 테두리 표시** (`tile_view.py`, `config.py`, `pdf_core.py`): 손상된 이미지(압축 파일의 체크섬과 맞지 않는 것, 일부만 읽히는 것)는 타일형/목록형 모두 빨간 굵은 테두리로 보입니다. 목록형에는 "손상됨(일부만 표시)" 글자도 붙습니다.
6. **rar가 열리지 않을 때 원인이 화면에 나오도록 개선** (`rar_tool.py`): 이전에는 마지막으로 시도한 도구의 실패만 보였습니다. 이제 시도한 모든 도구의 이름, 종료 코드, 도구가 낸 메시지를 줄마다 보여줍니다(윈도우 도구의 출력은 시스템 문자 코드로 읽어 글자가 깨지지 않게 했습니다). 실패 창 끝에는 내장 `UnRAR.exe`가 exe 안에 실제로 있는지와 크기도 한 줄로 보여줍니다.
7. **영문 이름 사본으로 재시도** (`rar_tool.py`): 경로에 한국어 문자 코드에 없는 글자가 있어서 도구가 실패하면, 같은 파일을 영문 이름(`archive.rar`)으로 가리키게 해서 같은 도구로 한 번 더 시도합니다(같은 드라이브면 하드링크라 복사가 없고, 아니면 복사하며 끝나면 지웁니다).

**확인한 것:** (a) 깨진 rar 샘플(5장 중 1장 손상): 5장이 모두 목록에 들어오고 손상된 1장만 표시되며 안내가 나옵니다. 메모리/디스크 방식 모두, PDF 내보내기까지 확인했습니다. 정상 rar는 안내가 없습니다. (b) 깨진 zip 샘플(저장 방식, 압축 방식 모두): 같은 결과입니다. (c) 이미 잘려 있는 JPEG/PNG는 읽히는 데까지 표시되고, 머리가 깨진 이미지는 빠지며 이름이 안내됩니다. (d) 화면에서 직접 확인했습니다. 손상된 타일만 빨간 테두리이고 읽히는 부분은 그대로 보입니다(타일형, 목록형 모두). (e) Windows용 `UnRAR.exe`가 `-kb`에서 같은 동작(종료 코드 3, 깨진 파일 남김)을 하는 것을 Wine에서 확인했습니다. (f) 도구 실패 시 이유가 줄마다 나오는 것, 한글이 아닌 경로에서 영문 이름 사본으로 재시도해 성공하는 것을 시험했습니다. (g) 기존 전체 테스트(분리 스모크, 드래그 막대, zip, 메모리/디스크, 키보드 이동, 툴바 줄바꿈, rar 읽기/앱 흐름)도 통과했습니다.
**확인하지 못한 것:** (a) **진짜 Windows에서의 실행**, 그리고 사용자의 실제 문제 파일로는 열어 보지 못했습니다. (b) v0.8.0에서 그 파일이 열리지 않은 정확한 이유는 확정하지 못했습니다. 손상 파일 때문이라는 설명이 증상과 맞아서 고쳤지만, 내장 UnRAR가 실제로 쓰였는지(백신 차단, exe 안에서 찾지 못함 등)는 이 화면만으로 알 수 없습니다. 다시 실패하면 이제 창에 원인이 나옵니다. (c) 윈도우 도구 출력을 시스템 문자 코드로 읽는 부분은 리눅스에서 시험할 수 없었습니다. (d) 압축 파일 끝(목차 부분)이 잘린 zip은 여전히 열리지 않습니다. (e) 옛 zip의 일본어/중국어 파일 이름 깨짐은 고치지 않았습니다(`ROADMAP.md`의 이름 처리 공용화에서 다룹니다).

### 받는 방법
이 릴리스의 소스는 위 태그(`v0.8.1`)의 소스 코드입니다. 압축을 풀고 폴더 구조를 그대로 둔 채 `build.bat`을 더블클릭하면 `dist\meltPDF.exe`가 만들어집니다(Python 3.9 이상 필요, 인터넷 필요). 자세한 사용법은 README.md, 전체 변경 이력은 CHANGELOG.md, 외부 소프트웨어 출처는 THIRD_PARTY_NOTICES.md를 보세요.
