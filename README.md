# 이미지 → PDF (무용지) 변환기

이미지 여러 장을 표준 용지 크기(A4 등)에 맞추지 않고, **각 이미지의 실제 크기 그대로** 한 페이지씩 담은 PDF를 만드는 Windows용 tkinter 프로그램입니다. (어도비 아크로뱃의 "용지 없이 이미지 붙이기"와 동일한 방식 — 이미지 픽셀 크기를 그대로 PDF 페이지 크기(MediaBox)로 사용합니다.) 이미지를 용지 크기에 끼워 맞추면 여백이 생기거나 이미지가 줄어들기 때문에, 이미지 한 장을 그 크기 그대로 한 페이지에 담는 PDF를 쉽게 만들고 싶어서 만들었습니다. (여러 이미지를 순서대로 정리하고, 이미 있는 PDF의 페이지 순서를 고치고, 압축/책 파일 안의 이미지를 꺼내 PDF로 만드는 것까지 한곳에서 합니다.)

프로그램 이름은 **meltPDF**입니다(v0.4.0까지는 Image2PDF였습니다).

## 실행 환경

- Windows 10/11 64비트용 프로그램입니다(tkinter 기반, 직접 만든 exe로 실행). 다른 운영체제는 지원하지 않습니다.
- 소스로 직접 실행하거나 exe를 만들려면 Python 3.9 이상이 필요합니다(윈도우용 파이썬에는 tkinter가 기본 포함되어 있습니다).
- exe를 만들 때(`build.bat`)와 처음 실행할 때 필요한 패키지를 내려받으므로 인터넷이 필요합니다.

## 실행 방법

```
pip install -r requirements.txt
python main.py
```

Windows에서 `python`이 3.9 이상이면 됩니다. (tkinter는 보통 Windows 파이썬 설치에 기본 포함되어 있습니다.)

## 기능

1. **이미지/폴더/압축 파일 추가** — 이미지 파일이나 폴더를 목록으로 드래그하면 자동으로 썸네일이 생성됩니다. (버튼으로도 추가 가능) zip/rar/cbz/cbr, 7z/cb7, tar/cbt(v0.16.0) 파일은 안의 이미지만 파일 이름 순서(2가 10보다 앞)로 꺼내서 넣습니다. **epub/fb2(v0.11.0), mobi/azw/azw3(v0.13.0), azw1/Topaz(v0.15.0, 삽화만):** 책 안의 이미지만 책을 읽는 순서대로 꺼냅니다(이름 순이 아님, 아래 "책 형식 지원" 참고). **djvu(v0.16.0):** 쪽마다 원래 해상도 그대로 풀어 PNG(무손실)로 넣습니다. rar/cbr은 프로그램에 같이 들어 있는 UnRAR로 풉니다(아래 "RAR/CBR 지원과 UnRAR.exe" 참고).
   **버튼:** 이미지, PDF, 압축/책 파일은 툴바의 [파일 열기/추가] 하나로 엽니다(여러 개를 한 번에 고를 수 있고, 끌어다 놓기와 같은 처리. 이전의 [이미지 추가], [기존 PDF 열기(수정)], [압축/책에서 이미지 추출]을 합친 것). 열 수 없는 형식의 파일은 건너뛰고 알립니다. 폴더는 [폴더 (이미지) 추가]로 넣습니다. 폴더 선택 창의 [폴더 선택] 버튼 옆에 있는 "서브 폴더의 이미지 파일도 전부 추가"를 체크하면 하위 폴더의 이미지까지 모두 넣고(목록 이름은 "하위폴더/파일"), 체크하지 않으면 그 폴더 바로 안의 이미지만 넣습니다(체크 상태는 기억됨). 폴더의 이미지는 zip과 같은 자연 정렬(2가 10보다 앞)입니다. 끌어다 놓은 폴더는 바로 안의 이미지를 넣고, 하위 폴더가 있으면 "서브 폴더를 검색할까요?"라고 묻습니다(바로 안에 이미지가 없으면 [검색]/[취소], 있으면 "이미지가 X장 있습니다. 서브 폴더를 추가로 검색할까요?" [검색]/[확인]). 불러오는 동안 가운데의 "이미지 불러오는 중..." 아래 [중단]을 누르면 그때까지 읽은 이미지만 넣고 멈춥니다(v0.17.3). 목록에 이미 썸네일이 보이는 채로 불러오는 중이면 하단 [전체 삭제] 옆의 [중단]이 같은 일을 합니다(v0.19.0, 불러오기가 끝나면 사라짐). **원하는 자리에 놓기(v0.19.0):** 목록에 이미지가 있을 때 탐색기에서 이미지/폴더/PDF/압축·책 파일을 썸네일 영역으로 끌어오면, 썸네일을 끌 때처럼 파란 막대로 들어갈 자리를 보여 주고 놓으면 그 자리에 넣습니다(여러 개를 한 번에 놓아도 놓은 순서 그대로 이어짐). 위/아래 끝 가까이로 끌면 조금씩 스크롤됩니다. 툴바 등 썸네일 영역 밖에 놓으면 맨 끝에 붙습니다.
2. **타일형 / 목록형 보기** — 툴바의 "보기" 라디오버튼으로 아이콘 그리드(타일형, 기본값)와 한 줄씩 자세히 보기(목록형)를 전환할 수 있습니다. 썸네일은 어느 모드에서든 잘리지 않고 이미지 전체 비율 그대로 표시됩니다. 타일은 가운데 정렬로 놓이고, 창 가장자리 여백은 타일 사이 간격의 두 배 이상입니다. 창이 넓어지면 타일 사이와 가장자리가 같은 간격으로 함께 벌어집니다(v0.19.4, 세로 간격은 고정). **화면 배치(v0.19.5):** 오른쪽 위에 큰 [PDF 내보내기] 버튼(툴바 두 줄 높이, 창 폭과 상관없이 고정), 하단 맨 오른쪽에 [설정](내보내기 버튼들과 넓게 띄움). 창은 툴바가 세 줄로 접히지 않는 폭보다 좁아지지 않습니다.
3. **순서 변경** — 썸네일을 마우스로 누른 채로 끌면, 그 썸네일 자체가 커서를 따라다니다가 원하는 위치에 놓으면 순서가 바뀝니다. PDF는 이 목록 순서대로 만들어집니다. 목록에서는 키보드로도 이동할 수 있습니다(방향키, Home/End, PageUp/PageDown - 이동한 항목이 선택되고 화면 밖이면 자동으로 스크롤).
4. **이미지 보기** — 썸네일을 두 번 누르면(또는 선택하고 Enter) 원본 크기의 이미지가 팝업 창으로 열립니다. 창 아래의 `-`(축소) `=`(창에 맞춤) `+`(확대) 버튼으로 크기를 바꾸고, 창보다 크게 확대하면 마우스로 끌어서 옮겨 볼 수 있습니다(마우스 휠은 가리킨 곳 기준 확대/축소, Esc는 닫기). **복사(v0.17.0):** 보기 창 아래 [+] 옆의 [복사 (Ctrl+C)] 버튼(또는 Ctrl+C)은 보고 있는 이미지를 원래 크기 그대로 클립보드에 그림으로 넣습니다(웹 브라우저의 "이미지 복사"와 같음). 그림판, 워드, 메신저 등에 바로 붙여 넣을 수 있습니다. 투명한 이미지는 투명도를 아는 프로그램에는 그대로, 그 밖에는 흰 바탕으로 들어갑니다. PDF 쪽은 보기 창에 그린 그림(긴 변 2600px)이 들어갑니다.
5. **표지 지정** — 항목을 선택하고 "선택 항목 표지로 지정"을 누르면 그 이미지가 항상 1페이지가 됩니다(목록에서의 위치와 무관). "표지 해제"로 취소할 수 있습니다.
6. **기존 PDF 편집** — [파일 열기/추가](또는 끌어다 놓기)로 이미 만들어진 PDF를 열면 각 페이지가 같은 목록에 들어와서 다른 페이지들과 똑같이 순서를 바꾸거나 삭제할 수 있습니다. **원본 페이지의 내용(텍스트, 벡터, 이미지 해상도 등)은 전혀 다시 그리거나 손상시키지 않습니다** — 화면 목록에 보여줄 작은 미리보기 썸네일만 별도로 렌더링할 뿐, "PDF로 내보내기"를 누르면 원본 페이지 객체를 그대로 복사해 넣습니다(순서 변경/삭제만 반영, 원본과 100% 동일한 화질·텍스트 선택/검색 기능 유지). **이미지 한 장뿐인 쪽(v0.20.1):** 이미지 한 장을 회전/뒤집기/잘라내기/늘리기 없이 그대로 놓은 쪽(보통의 스캔본, 이미지를 모아 만든 PDF)은 그 이미지(파일 안의 원래 바이트)를 꺼내 이미지 항목으로 넣습니다. 이 쪽은 PDF로 내보내면 다른 이미지처럼 이미지 크기의 쪽이 되고(원래 쪽 크기와 여백은 따르지 않음), 스캔본의 보이지 않는 검색용 글자(OCR)는 따라가지 않습니다. 회전/뒤집기/잘라내기/늘리기가 있는 쪽, 이미지가 여러 장인 쪽, 보이는 글자나 선/도형/주석이 있는 쪽, 특수한 색 공간이나 마스크를 쓴 이미지, 암호가 걸렸거나 복사를 막은 PDF는 예전처럼 쪽 그대로 넣습니다. 불러온 뒤 상태 줄에 "N쪽 중 K쪽은 이미지로 꺼냈고, 나머지는 쪽 그대로"를 보여 줍니다.
7. **PDF 내보내기** — 창 오른쪽 위의 큰 [PDF 내보내기] 버튼(v0.19.5, 이전에는 하단의 [PDF로 내보내기])을 누르면 최종 목록을 위 규칙(표지 우선, 무용지 페이지 크기, 기존 페이지는 원본 그대로)대로 PDF 파일로 저장합니다. **저장 창(v0.20.0):** 파일 하나 또는 폴더 하나만 불러왔으면 저장 창이 그 파일/폴더가 있는 위치에서 열리고, 기본 이름은 "원본이름_Reprint.pdf"입니다(예: `D:\책\book.epub` -> `D:\책\book_Reprint.pdf`, `D:\사진\여행` 폴더 -> `D:\사진\여행_Reprint.pdf`. 원본이 PDF여도 이름이 달라 덮어쓰지 않음). 여러 개를 불러왔으면 처음 불러온 것의 이름.pdf이고 위치는 윈도우가 정합니다.
8. **이미지 내보내기** — 하단 오른쪽의 [전체 이미지 내보내기](이전 이름: 이미지 내보내기)를 누르면 목록의 이미지를 파일로 풀어 줍니다. 팝업의 세 버튼 중 하나를 고릅니다: [원본 파일 위치에 폴더 생성 후 풀기] / [설정 폴더에 폴더 생성 후 풀기](설정 창의 "이미지 내보내기 기본 폴더") / [찾아보기]. 처음 불러온 파일 이름으로 새 폴더를 만들고(이미 있으면 "이름 (1)"), 압축 파일 안의 하위 폴더는 만들지 않고 한 폴더에 펼칩니다. 이름이 겹치면 "이름 (1).jpg"처럼 번호를 붙이고 어떤 이름이 바뀌었는지 안내 창으로 알립니다. 원본 바이트를 그대로 저장하지만, 회전 정보를 반영했거나 손상되어 일부만 읽은 이미지는 목록에 담긴 PNG로 저장됩니다(확장자는 내용에 맞게 .png). **PDF에서 가져온 쪽(v0.12.0):** 쪽을 그림으로 그리는 것이 아니라 그 쪽 안에 든 원본 이미지를 꺼내 저장합니다. JPEG는 PDF 안의 바이트 그대로, 그 밖의 형식은 같은 픽셀의 PNG로 나오고(투명 마스크가 있으면 투명 PNG), 파일 이름은 "PDF이름 - p003.jpg"이며 한 쪽에 이미지가 여러 장이면 "- p003_1.jpg", "_2"입니다. 같은 이미지를 여러 쪽이 쓰면 한 번만 저장하고, 글자만 있는 쪽처럼 꺼낼 이미지가 없는 쪽은 건너뛰며 개수를 알립니다. 회전·잘라내기 같은 쪽 설정은 반영하지 않아 스캔본이 옆으로 누워 나올 수 있습니다. 암호가 필요하거나 내용 복사를 막아 둔 PDF는 꺼내지 않습니다. 순서를 바꾸거나 지운 목록 그대로 적용됩니다.
   **선택된 이미지 내보내기:** 그 옆의 [선택된 이미지 내보내기]는 목록에서 선택한 이미지만 묻지 않고 원본 파일 위치(처음 불러온 파일이 있는 폴더)에 바로 저장하고 "원본 파일 위치에 파일을 저장했습니다." 안내를 띄웁니다. 새 폴더는 만들지 않고, 여러 개를 선택했으면 목록 순서대로 모두 저장합니다. 이름과 내용 규칙은 전체 내보내기와 같고(PDF 쪽은 그 쪽 안의 원본 이미지), 같은 이름의 파일이 이미 있으면 덮어쓰지 않고 " (1)"을 붙입니다.
9. **서지 정보(Metadata) (v0.14.0)** — epub, fb2, mobi/azw/azw3, azw1(v0.15.0), djvu(v0.16.0), PDF를 불러오면 파일 안의 서지 정보(제목, 저자, 설명/주제, 키워드, 출판사, 언어, 출판일, ISBN 등 식별자)를 같이 읽습니다. 툴바의 [설정] 옆 [서지 정보(Metadata)]에서 확인하고 고칠 수 있고, PDF로 내보낼 때 PDF 문서 속성(제목/저자/주제/키워드)과 XMP 서지 정보로 들어갑니다(언어는 문서 언어에도). 여러 파일을 불러오면 서지 정보가 있는 첫 파일의 값이 들어가고, 창에서 다른 파일의 정보로 바꿔 채울 수 있습니다. 직접 고친 뒤에는 다른 파일을 더 불러와도 바뀌지 않습니다. zip/rar/cbz/cbr/7z/cb7/tar/cbt와 이미지에는 서지 정보가 없어 빈 칸이며, 직접 입력하면 그대로 들어갑니다. 비워 둔 칸은 넣지 않고, 목록을 모두 지우면 서지 정보도 비워집니다. 출판일은 2020 / 2020-05 / 2020-05-17, 언어는 ko / en-US 같은 꼴만 저장됩니다.

## 동작 방식 / 알아두면 좋은 점

- **새로 추가한 이미지 파일**의 페이지 크기는 이미지의 픽셀 크기와 DPI 정보로 결정됩니다. 이미지에 DPI 정보가 없으면 96dpi로 가정합니다(일반적인 스크린샷 등). 스캔한 이미지처럼 DPI가 박혀 있으면 그 값을 그대로 사용합니다. 회전 정보(EXIF Orientation)가 있는 사진은 보이는 방향대로 회전을 반영해서 넣습니다. 일반 이미지는 재인코딩 없이 원본 파일을 그대로 PDF에 담아 화질 손실이 없습니다.
- **PDF에서 쪽 그대로 불러온 페이지는 원본을 절대 건드리지 않습니다**(이미지 한 장뿐이라 이미지로 꺼낸 쪽은 위 6번 참고). 화면 목록/썸네일에 보여주기 위한 작은 미리보기만 그때그때 렌더링하고, 실제 "PDF로 내보내기"를 할 때는 그 페이지의 원본 데이터를 그대로 복사해서 새 PDF에 넣습니다. 그래서 텍스트였던 PDF는 내보낸 뒤에도 여전히 텍스트를 선택/검색할 수 있고, 화질도 원본 그대로입니다. 이 프로그램이 할 수 있는 건 어떤 페이지를 넣고 뺄지, 순서를 어떻게 할지뿐이고 페이지 내용 자체는 절대 바꾸지 않습니다.
- **zip 안의 일본어/중국어/한국어 이름(v0.10.0):** UTF-8 표시가 없는 zip은 이름의 글자 인코딩을 알 수 없어서, 압축 파일 전체의 이름들을 보고 UTF-8/cp949/cp932(일본어)/gbk(간체)/big5(번체) 중 가장 그럴듯한 것을 고릅니다(`name_codec.py`). 한자만으로 된 짧은 이름은 일본어/중국어/한국어를 바이트로 구별할 수 없어 한국어를 우선하므로, 파일이 하나뿐인 zip의 짧은 중국어 이름은 틀릴 수 있습니다.
- **끝이 잘린 zip(v0.10.1):** 다운로드가 끊겨 목차가 없는 zip도 앞에서부터 읽어 이미지를 복구하고, 중간에서 끊긴 이미지는 빨간 테두리로 표시하며 복구했다는 안내를 함께 보여줍니다. 저장/deflate 방식만 지원합니다.
- **RAR 메모리 방식(v0.10.2):** 메모리에 두는 rar/cbr은 임시 폴더 없이 UnRAR 출력으로 바로 받습니다(아래 "RAR/CBR 지원과 UnRAR.exe" 참고).
- **깨진 이미지(v0.19.6):** 깨진 이미지는 빼지 않고 모두 목록에 넣고 빨간 테두리로 구분합니다.
  - 일부만 읽히면 읽힌 부분만 보여 주고 PDF에도 그대로 넣습니다.
  - 파일 앞부분이 깨진 PNG/JPEG는 머리 부분을 복구해 다시 읽어 봅니다(다 풀리면 그림 전체가 살아남).
  - 전혀 못 읽는 파일(빈 파일, 이미지가 아닌 파일 등)은 빈 상자에 X자 썸네일로 넣습니다. PDF에는 그 자리에 빈 쪽이 들어가고, 쪽 크기는 머리에서 찾은 크기, 못 찾으면 바로 앞 쪽과 같습니다. 이미지 내보내기는 원본 파일을 그대로 저장합니다.
  - 하단 [깨진 이미지 N장]을 누르면 목록 맨 앞부터 차례로 깨진 이미지를 선택해 화면 가운데로 보여 줍니다.
- **불러오기 속도(v0.18.0):** 이미지를 여러 장 동시에 읽고(코어 수에 맞춰 최대 8장), JPEG는 썸네일에 필요한 만큼만 작게 풀며, 읽은 이미지는 다 끝날 때까지 기다리지 않고 몇십 장씩 목록에 먼저 나타납니다(순서는 넣은 순서 그대로). 폴더/이미지 파일과 압축/책 파일 모두 해당하고, PDF 쪽은 예전처럼 한 장씩 그립니다. 내보내기는 원본을 그대로 쓰므로 결과물 화질과는 상관없습니다. **수천 장(v0.19.2~v0.19.3):** 화면에는 보이는 곳 + 위아래 한 화면의 타일만 그리고(스크롤하면 바꿔 그림), 썸네일 스레드는 화면을 기다리지 않으므로 목록이 길어져도 불러오기와 화면이 느려지지 않습니다(6,000장 시험).
- **메모리 사용(v0.10.1):** 하단 오른쪽의 "메모리 N MB | PC N%"는 이 프로그램이 쓰는 메모리와 컴퓨터 전체 사용률입니다. PDF를 만들 때는 이미지 총량의 약 1배(결과 PDF 크기)만큼 메모리를 씁니다(이전 약 2배).

## 책 형식 지원 (v0.11.0: epub, fb2 / v0.13.0: mobi, azw, azw3 / v0.15.0: azw1 / v0.16.0: djvu)

epub, fb2, mobi 계열에서는 **이미지만** 꺼냅니다(글은 쓰지 않습니다). 서지 정보는 함께 읽어 PDF에 넣을 수 있습니다(위 기능 9). 이미지는 다시 압축하지 않고 원본 그대로 가져옵니다. zip/rar와 달리 **이름 순이 아니라 책에 나오는 순서**입니다.

- **epub:** `content.opf`의 쪽 순서(spine)대로 각 쪽의 `<img>`와 `<svg><image>`를 만나는 순서로 모읍니다. 같은 이미지를 여러 쪽에서 쓰면 처음 자리에만 넣고, 표지로 지정된 이미지(cover-image)는 쪽에서 쓰지 않아도 맨 앞에 넣습니다. 글 위주 epub은 "이미지가 들어 있지 않습니다"로 나옵니다.
- **fb2:** 문서에 `<image>`가 나오는 순서(표지 -> 본문)입니다. 이름은 이미지의 id(+내용에 맞춘 확장자)입니다. 본문에서 쓰지 않는 이미지는 빼고, 본문에서 쓰는 이미지가 하나도 없을 때만 파일에 들어 있는 순서로 넣습니다. `.fb2.zip`(zip 안에 fb2 하나)도 열립니다.
- **mobi / azw / azw3(v0.13.0):** 킨들 계열 책입니다. 파일 안에는 이미지가 저장된 순서와 책에 나오는 순서가 다르므로, 본문을 풀어서 이미지가 나오는 자리(`<img recindex>`, azw3는 `kindle:embed`)를 찾아 그 순서대로 넣습니다. 표지(EXTH 표지 지정)는 맨 앞, 같은 이미지는 한 번만, 썸네일은 뺍니다. 이름은 `image_00001.jpg`처럼 붙습니다. 본문 압축이 Huffman(CDIC)인 옛 파일은 아직 풀지 못해 **파일에 저장된 순서**로 넣고 그 사실을 안내합니다. mobi와 azw3가 한 파일에 같이 든 파일은 mobi 쪽만 읽습니다.
- **azw1 / Topaz(.azw1, .tpz, 일부 .azw)(v0.15.0):** 킨들의 옛 형식으로, 쪽이 이미지가 아니라 글자 모양(glyph)과 위치로 저장되어 있습니다. 쪽을 다시 그리지 않고 **파일에 이미지로 들어 있는 삽화/표지만** 꺼냅니다. 같은 번호의 컬러판이 있으면 컬러판을 씁니다. 순서는 파일에 저장된 이미지 번호 순이라 책 순서와 다를 수 있습니다. 이름은 `image_00001.jpg` 꼴입니다. 서지 정보(제목, 저자, 출판사 등)도 읽습니다. 끝이 잘린 파일은 남은 이미지만 넣고, 중간에서 끊긴 이미지는 손상 표시를 합니다.
- **djvu(.djvu, .djv)(v0.16.0):** djvu의 쪽은 JPEG/PNG 같은 이미지 파일이 아니라 흑백 글자층, 배경층, 전경 색으로 나뉘어 djvu 전용 압축으로 들어 있습니다. 그대로 꺼내면 열 수 있는 프로그램이 없으므로, 프로그램에 같이 들어 있는 DjVuLibre(`tools/ddjvu.exe`)로 쪽을 **크기 변경 없이(원래 해상도)** 풀어 PNG(무손실)로 넣습니다. "원본 바이트"는 아니지만 "원본 픽셀"은 그대로입니다. 흑백 쪽은 1비트 PNG, 컬러 쪽은 RGB PNG이고, 쪽 순서대로 `page_0001.png`처럼 이름이 붙습니다. 쪽의 원래 dpi를 PNG에 적어 두므로 PDF로 내보내면 스캔 이미지와 같은 규칙으로 쪽이 원래 종이 크기가 됩니다. 깨진 쪽은 건너뛰고 몇 쪽인지 알립니다. 서지 정보(title, author, subject, keywords, publisher, year 등)도 읽습니다. 출처와 라이선스(GPL-2.0 이상)는 `tools/README.md`와 `THIRD_PARTY_NOTICES.md`.
- **7z/cb7, tar/cbt(v0.16.0):** 압축 파일이라 zip/rar처럼 이름 순입니다. 7z는 py7zr로 풀고, 암호가 걸린 7z는 열지 않습니다. 7z는 목차가 파일 끝에 있어 끝이 잘린 7z는 열 수 없습니다. tar는 gzip/bzip2/xz로 압축한 tar(.tar.gz 등)도 열리고, 끝이 잘린 tar는 읽힌 데까지 넣습니다.
- **파일 종류는 확장자가 아니라 내용으로 판별합니다.** `.zip`이라는 이름의 epub도 epub로 읽습니다.
- **DRM(저작권 보호)이 걸린 epub/mobi/azw/azw1은 열지 않습니다**(우회하지 않습니다). 글꼴만 가리는 난독화는 DRM이 아니라서 무시합니다.
- 지원하지 않는 형식: kfx(킨들 최신 형식, 구조 비공개), xps/oxps, chm, lit(ROADMAP 참고). PDF는 "파일 열기/추가"로 쪽을 목록에 넣은 뒤 [이미지 내보내기]로 쪽 안의 원본 이미지를 저장합니다(위 기능 8).

## RAR/CBR 지원과 UnRAR.exe

RAR 압축을 푸는 파이썬 라이브러리는 없어서, 공식 **UnRAR**(RARLAB, Alexander Roshal)을 `tools/UnRAR.exe`로 프로그램에 같이 넣었습니다(`build.bat`이 exe 안에 포함시킵니다). 그래서 **7-Zip이나 WinRAR을 따로 설치하지 않아도** rar/cbr이 열립니다. UnRAR 라이선스는 RAR를 푸는 용도로 다른 프로그램에 넣어 배포하는 것을 허용합니다(RAR 압축을 *만드는* 데는 쓸 수 없음).

- 출처, 정확한 버전, 만든 방법, 소스 수정 내역(코드 한 줄 + 유니코드 명령줄 컴파일 옵션), SHA-256, 라이선스 전문: [`tools/README.md`](tools/README.md)
- 쓰는 모든 외부 소프트웨어의 출처/라이선스와 검토했지만 쓰지 않은 것들: [`THIRD_PARTY_NOTICES.md`](THIRD_PARTY_NOTICES.md)
- 예비 순서: 같이 들어 있는 UnRAR.exe를 쓸 수 없으면 사용자가 exe 옆에 둔 UnRAR.exe/7z.exe -> 설치된 WinRAR/7-Zip -> PATH의 도구 -> 윈도우 기본 `tar.exe` 순으로 시도합니다.
- **메모리 방식이면 디스크에 쓰지 않습니다(v0.10.2):** 메모리에 두는 경우(기본 설정에서 한도 안이면 메모리에 둡니다) 같이 들어 있는 UnRAR의 표준 출력(`p` 명령)으로 이미지를 바로 메모리에 받습니다. 목차의 크기대로 잘라 이미지는 CRC32까지 맞는지 확인하고, 하나라도 어긋나거나 도구가 실패하면 예전처럼 디스크 임시 폴더에 풀어서 읽습니다(손상된 파일 처리는 그쪽이 맡습니다). 디스크 방식을 고른 경우는 이전과 같이 임시 폴더에 풀었다가 끝나면 지웁니다. 암호가 걸린 rar는 지원하지 않습니다.
- **손상된 파일이 있어도 열립니다(v0.8.1):** rar/zip 안의 일부 파일이 깨져 있으면, 깨진 파일은 읽을 수 있는 데까지 불러와서 타일에 **빨간 테두리**로 표시하고 "손상된 이미지 N개가 있습니다" 안내로 어떤 파일인지 알려 줍니다(폴더나 이미지를 직접 추가할 때도 같습니다). 파일 맨 앞이 깨져 이미지로 인식되지 않는 것만 목록에서 뺍니다. 압축 풀기가 실패하면 시도한 모든 도구의 실패 이유가 창에 나옵니다.
- 압축 파일 주석은 읽지 않습니다(RAR 3/4의 압축된 주석을 읽으려면 별도 unrar 도구가 필요해서, 목차를 읽는 단계에서 파일이 열리지 않는 원인이 되었습니다 - v0.8.0).
- 압축 파일 경로나 안의 파일 이름에 일본어/중국어 등 한국어 윈도우 문자 코드(cp949)에 없는 글자가 있어도 되도록, 같이 들어 있는 UnRAR.exe는 명령줄을 유니코드로 받게 컴파일했습니다(v0.8.0).

새 기능을 넣을 때: 자기 파일을 새로 만들고, 목록을 바꿀 땐 `DocModel` 메서드를 통해서만 바꾸고, `app_window.py`에서는 객체를 만들고 버튼 한 줄만 추가합니다. 타일 영역(`tile_view.py`)에는 자식 위젯을 넣지 않습니다(캔버스 아이템으로만 그림) - 위젯이 겹치면 드래그 때 얼룩이 생기는 문제가 다시 살아납니다.

## Windows 실행 파일(.exe)로 만들기

압축을 풀고 **`build.bat`을 더블클릭**하면 됩니다. 알아서 다음을 순서대로 처리합니다:

1. Python 설치 여부 확인
2. `venv` 가상환경 생성
3. `requirements.txt` + `pyinstaller` 설치 (인터넷 필요)
4. `pyinstaller`로 `meltPDF.exe` 하나로 빌드 (`--onefile --windowed`)

빌드가 끝나면 `dist\meltPDF.exe`가 탐색기로 자동으로 열립니다. 이 exe 파일 하나만 복사해서 아무 폴더에서나 실행하면 됩니다(파이썬 설치 없이도 동작).

- Python이 없다면 먼저 https://www.python.org/downloads/ 에서 설치하세요. 설치 화면에서 **"Add python.exe to PATH"를 꼭 체크**해야 `build.bat`이 python을 찾을 수 있습니다.
- 처음 실행하면 패키지 다운로드 때문에 몇 분 걸릴 수 있습니다. 이후 다시 빌드할 때는(코드가 바뀌었을 때) `venv` 폴더가 남아있어서 더 빠릅니다.
- **탐색기에서 exe 아이콘이 예전 것으로 보이면** 윈도우 아이콘 캐시 때문일 수 있습니다(같은 위치에 같은 이름으로 다시 빌드하면 예전 그림을 보여 주는 경우가 있음). exe 파일 이름을 바꿔 보거나, 명령 프롬프트에서 `ie4uinit.exe -show`를 실행하면 새로 읽습니다. 아이콘 그림 자체는 exe 안에 들어 있습니다(v0.17.3에서 빌드한 exe를 열어 16~256px 9개 크기가 모두 들어 있는 것을 확인).
- **버그 리포트(v0.19.1, 위치/이름/알림은 v0.19.2):** 오류가 나거나 프로그램이 갑자기 꺼지면 **`meltPDF.exe`가 있는 폴더**에 버그 리포트 `meltpdf_버전_bug_report_yyyymmddHHMMSS.txt`(예: `meltpdf_0192_bug_report_20261014153012.txt`)가 생깁니다. 이 파일 하나를 보내 주면 됩니다. exe 폴더에 쓸 수 없을 때만(Program Files 등) `%APPDATA%\meltPDF\logs`에 만들고 알림 창에 위치를 보여 줍니다.
  - 보고서 내용: 프로그램/윈도우/파이썬 버전, 그때의 상태(목록 장수, 진행 중인 불러오기 수, 창 크기, 화면 배율), 오류가 난 코드 위치, 최근 활동 기록(끌어다 놓기, 불러오기 작업, 목록 변경, 내보내기 등). 파일은 이름만 남고 전체 경로는 남지 않습니다.
  - 화면 쪽 오류: 바로 보고서를 만들고 알림 창(프로그램은 계속 동작). 갑자기 꺼짐(파이썬 바깥의 충돌 포함, 작업 관리자로 끈 경우도): 다음에 켤 때 "크래시 감지. [보고서 파일 이름]이 생성되었습니다." + 위치를 보여 주고 폴더를 열지 묻습니다. 화면이 10초 넘게 멈추면 그때의 실행 위치도 기록에 남습니다.
  - 오류 창이 없던 문제(이상한 동작, 느림)는 [설정] -> [버그 리포트 만들기]로 지금 상태와 기록을 담은 보고서를 exe 옆에 만들 수 있습니다. 보고서는 최근 20개만 남기고 오래된 것은 지웁니다(exe 폴더의 `meltpdf_*_bug_report_*.txt`만 대상).
  - 보고서의 재료인 활동 기록 `meltPDF_log.txt`(지난번 실행분 `meltPDF_log_prev.txt`)는 `%APPDATA%\meltPDF\logs`에 있습니다(따로 찾을 필요 없음).
  - (v0.19.0까지는 오류가 `meltPDF.exe` 옆의 `crash_log.txt`에 남았습니다.)
- 소스 코드 자체는 가상 디스플레이에서 실행해 화면 렌더링, 타일형/목록형 전환, 표지 지정/해제, 삭제, 이미지 추가, 기존 PDF 열기, PDF 내보내기까지 자동 테스트를 통과한 상태입니다. **다만 드래그로 순서 바꾸는 동작은 실제 Windows 마우스 캡처/렌더링 방식이 가상 디스플레이 자동 테스트로는 재현되지 않아서, 실사용 중에만 드러나는 버그가 몇 차례 있었습니다.**

- 버전별 변경 이력(무엇을 왜 바꿨고 무엇을 확인했는지)은 [CHANGELOG.md](CHANGELOG.md)에 있습니다. 같은 내용이 GitHub의 각 버전 태그/릴리스 설명에도 올라갑니다.
