# 이미지 → PDF (무용지) 변환기

이미지 여러 장을 표준 용지 크기(A4 등)에 맞추지 않고, **각 이미지의 실제 크기 그대로** 한 페이지씩 담은 PDF를 만드는 Windows용 tkinter 프로그램입니다. (어도비 아크로뱃의 "용지 없이 이미지 붙이기"와 동일한 방식 — 이미지 픽셀 크기를 그대로 PDF 페이지 크기(MediaBox)로 사용합니다.) 이미지를 용지 크기에 끼워 맞추면 여백이 생기거나 이미지가 줄어들기 때문에, 이미지 한 장을 그 크기 그대로 한 페이지에 담는 PDF를 쉽게 만들고 싶어서 만들었습니다. (여러 이미지를 순서대로 정리하고, 이미 있는 PDF의 페이지 순서를 고치고, 압축/책 파일 안의 이미지를 꺼내 PDF로 만드는 것까지 한곳에서 합니다.)

프로그램 이름은 **meltPDF**입니다(v0.4.0까지는 Image2PDF였습니다).

## 실행 환경

- Windows 10/11 64비트용 프로그램입니다(tkinter 기반, 직접 만든 exe로 실행). 다른 운영체제는 지원하지 않습니다.
- 소스로 직접 실행하거나 exe를 만들려면 Python 3.9 이상이 필요합니다(윈도우용 파이썬에는 tkinter가 기본 포함되어 있습니다).
- exe를 만들 때(`build.bat`)와 처음 실행할 때 필요한 패키지를 내려받으므로 인터넷이 필요합니다.

## 실행 방법

```
pip install -r requirements.txt
python main.py
```

Windows에서 `python`이 3.9 이상이면 됩니다. (tkinter는 보통 Windows 파이썬 설치에 기본 포함되어 있습니다.)

## 기능

1. **이미지/폴더/압축 파일 추가** — 이미지 파일이나 폴더를 목록으로 드래그하면 자동으로 썸네일이 생성됩니다. (버튼으로도 추가 가능) zip/rar/cbz/cbr 파일은 안의 이미지만 파일 이름 순서(2가 10보다 앞)로 꺼내서 넣습니다. rar/cbr은 컴퓨터에 압축 해제 도구(7-Zip, WinRAR 또는 UnRAR.exe)가 있어야 열립니다(아래 "RAR 도구" 참고).
2. **타일형 / 목록형 보기** — 툴바의 "보기" 라디오버튼으로 아이콘 그리드(타일형, 기본값)와 한 줄씩 자세히 보기(목록형)를 전환할 수 있습니다. 썸네일은 어느 모드에서든 잘리지 않고 이미지 전체 비율 그대로 표시됩니다.
3. **순서 변경** — 썸네일을 마우스로 누른 채로 끌면, 그 썸네일 자체가 커서를 따라다니다가 원하는 위치에 놓으면 순서가 바뀝니다. PDF는 이 목록 순서대로 만들어집니다. 목록에서는 키보드로도 이동할 수 있습니다(방향키, Home/End, PageUp/PageDown - 이동한 항목이 선택되고 화면 밖이면 자동으로 스크롤).
4. **표지 지정** — 항목을 선택하고 "선택 항목 표지로 지정"을 누르면 그 이미지가 항상 1페이지가 됩니다(목록에서의 위치와 무관). "표지 해제"로 취소할 수 있습니다.
5. **기존 PDF 열기(수정)** — 이미 만들어진 PDF를 열면 각 페이지가 같은 목록에 들어와서 다른 페이지들과 똑같이 순서를 바꾸거나 삭제할 수 있습니다. **원본 페이지의 내용(텍스트, 벡터, 이미지 해상도 등)은 전혀 다시 그리거나 손상시키지 않습니다** — 화면 목록에 보여줄 작은 미리보기 썸네일만 별도로 렌더링할 뿐, "PDF로 내보내기"를 누르면 원본 페이지 객체를 그대로 복사해 넣습니다(순서 변경/삭제만 반영, 원본과 100% 동일한 화질·텍스트 선택/검색 기능 유지).
6. **PDF로 내보내기** — 최종 목록을 위 규칙(표지 우선, 무용지 페이지 크기, 기존 페이지는 원본 그대로)대로 PDF 파일로 저장합니다.

## 동작 방식 / 알아두면 좋은 점

- **새로 추가한 이미지 파일**의 페이지 크기는 이미지의 픽셀 크기와 DPI 정보로 결정됩니다. 이미지에 DPI 정보가 없으면 96dpi로 가정합니다(일반적인 스크린샷 등). 스캔한 이미지처럼 DPI가 박혀 있으면 그 값을 그대로 사용합니다. 회전 정보(EXIF Orientation)가 있는 사진은 보이는 방향대로 회전을 반영해서 넣습니다. 일반 이미지는 재인코딩 없이 원본 파일을 그대로 PDF에 담아 화질 손실이 없습니다.
- **"기존 PDF 열기"로 불러온 페이지는 원본을 절대 건드리지 않습니다.** 화면 목록/썸네일에 보여주기 위한 작은 미리보기만 그때그때 렌더링하고, 실제 "PDF로 내보내기"를 할 때는 그 페이지의 원본 데이터를 그대로 복사해서 새 PDF에 넣습니다. 그래서 텍스트였던 PDF는 내보낸 뒤에도 여전히 텍스트를 선택/검색할 수 있고, 화질도 원본 그대로입니다. 이 프로그램이 할 수 있는 건 어떤 페이지를 넣고 뺄지, 순서를 어떻게 할지뿐이고 페이지 내용 자체는 절대 바꾸지 않습니다.

## 소스 구성 (개발 지침: 기능 하나 = 파일 하나, 파일당 가급적 800줄 이하)

수정할 때 다른 기능을 실수로 건드리지 않도록 기능별로 파일을 나눠 두었습니다. 파일끼리는 `doc_model.py`의 알림(subscribe)으로만 연결되므로, 한 기능을 고칠 때 다른 기능 파일을 열 일이 없습니다.

| 파일 | 맡은 기능 |
|---|---|
| `main.py` | 실행 진입점 (창 만들고 시작) |
| `app_window.py` | 메인 창 조립 - 기능 객체를 만들어 연결하고 툴바/하단바 버튼만 배치 (로직 없음) |
| `config.py` | 공용 상수 (이름/버전, 타일 치수, 색상, 드래그앤드롭 사용 가능 여부) |
| `doc_model.py` | 페이지 목록·순서·선택·표지 데이터와 변경 알림 (화면을 모름) |
| `tile_view.py` | 썸네일 타일을 캔버스에 그리기, 스크롤, 창 크기 변화, 타일 위치 계산 |
| `selection.py` | 클릭/Ctrl+클릭 선택 |
| `key_nav.py` | 키보드 이동 (방향키, Home/End, PageUp/PageDown으로 선택 이동, 화면 밖이면 자동 스크롤) |
| `drag_reorder.py` | 끌어서 순서 바꾸기 (유령 썸네일, 파란 삽입 막대) |
| `file_loader.py` | 이미지/폴더/PDF 불러오기, 드래그앤드롭 받기 |
| `load_queue.py` | 불러오기 작업을 넣은 순서대로 하나씩 처리하는 공용 대기열 |
| `book_loader.py` | 압축/책 파일(zip, rar, cbz, cbr 등)에서 이미지 추출 - 파일 선택/드롭/진행 표시/오류 안내 |
| `book_import.py` | 책/압축 파일 종류를 파일 앞부분(시그니처)으로 판별해 알맞은 읽기 모듈로 넘김 |
| `archive_rar.py` | rar/cbr 읽기 (이름 순, 암호/폭탄/손상 거절) - 목차는 rarfile로 읽고 풀기는 rar_tool에 맡김 |
| `rar_tool.py` | RAR를 풀어 줄 도구 찾기/실행 (UnRAR, 7-Zip, unar, bsdtar/윈도우 tar 순, 실패하면 다음 도구) |
| `archive_zip.py` | zip/cbz 읽기 (이름 순, 한글 이름 복원, 암호/폭탄 거절) |
| `natural_sort.py` | 이름 자연 정렬 규칙 (2 < 10, 폴더 단위 비교, 대소문자 무시) - 압축 파일 정렬에 사용 |
| `book_common.py` | 책/압축 읽기 공통 부분 (오류 종류, 결과 자료형, 이미지 이름 판정) |
| `temp_store.py` | 디스크를 쓸 때 꺼낸 이미지를 두는 임시 폴더 (프로그램 종료 시 삭제) |
| `storage_policy.py` | 꺼낸 이미지를 메모리/디스크 중 어디에 둘지 결정 (기본 메모리, 한도 초과 시 묻기) |
| `memory_info.py` | 지금 남은 메모리 크기 알아내기 |
| `settings.py` | 설정 저장/읽기 (JSON) |
| `settings_dialog.py` | 설정 창 (저장 위치, 메모리 한도) |
| `rename_pages.py` | 파일명 변경하기 (접두사 + 4자리 번호, 현재 순서 기준) |
| `page_actions.py` | 표지 지정/해제, 선택 삭제, 전체 삭제 |
| `export.py` | PDF 내보내기 실행 (저장 위치, 백그라운드 실행, 결과 안내) |
| `status_bar.py` | 하단 상태 문구 |
| `wrapbar.py` | 창이 좁아지면 줄바꿈되는 툴바 컨테이너 |
| `crash_log.py` | 오류를 `crash_log.txt`와 메시지박스로 기록 |
| `pdf_core.py` | PDF 생성/읽기 핵심 로직 (GUI와 무관) |

## RAR 도구 (rar/cbr을 열 때 필요)

RAR 압축을 푸는 방법은 라이선스상 UnRAR 계열 도구만 쓸 수 있어서, 이 프로그램은 직접 풀지 않고 컴퓨터에 있는 도구에 맡깁니다. 아래 중 **하나만** 있으면 됩니다(위에 있는 것이 우선):

1. `UnRAR.exe`를 `meltPDF.exe`와 같은 폴더(또는 그 안의 `tools` 폴더)에 넣기
2. **7-Zip** 설치 (무료, https://7-zip.org) 또는 **WinRAR** 설치
3. 윈도우 10/11에 기본으로 들어 있는 `tar.exe`(연속(solid) 압축 rar는 못 풀 수 있음)

어느 것도 없으면 열 때 안내 창이 뜹니다. 풀리는 동안만 디스크 임시 폴더를 쓰고 끝나면 지웁니다(메모리 방식이어도 마찬가지). 암호가 걸린 rar는 지원하지 않습니다.

새 기능을 넣을 때: 자기 파일을 새로 만들고, 목록을 바꿀 땐 `DocModel` 메서드를 통해서만 바꾸고, `app_window.py`에서는 객체를 만들고 버튼 한 줄만 추가합니다. 타일 영역(`tile_view.py`)에는 자식 위젯을 넣지 않습니다(캔버스 아이템으로만 그림) - 위젯이 겹치면 드래그 때 얼룩이 생기는 문제가 다시 살아납니다.

## Windows 실행 파일(.exe)로 만들기

압축을 풀고 **`build.bat`을 더블클릭**하면 됩니다. 알아서 다음을 순서대로 처리합니다:

1. Python 설치 여부 확인
2. `venv` 가상환경 생성
3. `requirements.txt` + `pyinstaller` 설치 (인터넷 필요)
4. `pyinstaller`로 `meltPDF.exe` 하나로 빌드 (`--onefile --windowed`)

빌드가 끝나면 `dist\meltPDF.exe`가 탐색기로 자동으로 열립니다. 이 exe 파일 하나만 복사해서 아무 폴더에서나 실행하면 됩니다(파이썬 설치 없이도 동작).

- Python이 없다면 먼저 https://www.python.org/downloads/ 에서 설치하세요. 설치 화면에서 **"Add python.exe to PATH"를 꼭 체크**해야 `build.bat`이 python을 찾을 수 있습니다.
- 처음 실행하면 패키지 다운로드 때문에 몇 분 걸릴 수 있습니다. 이후 다시 빌드할 때는(코드가 바뀌었을 때) `venv` 폴더가 남아있어서 더 빠릅니다.
- 빌드나 실행 중 오류가 나면 `meltPDF.exe`와 같은 폴더에 `crash_log.txt`가 자동으로 남습니다(창이 없는 windowed 모드라 오류가 안 보일 수 있어서, 오류를 파일로도 남기고 메시지창도 띄우도록 만들어 뒀습니다).
- 소스 코드 자체는 가상 디스플레이에서 실행해 화면 렌더링, 타일형/목록형 전환, 표지 지정/해제, 삭제, 이미지 추가, 기존 PDF 열기, PDF 내보내기까지 자동 테스트를 통과한 상태입니다. **다만 드래그로 순서 바꾸는 동작은 실제 Windows 마우스 캡처/렌더링 방식이 가상 디스플레이 자동 테스트로는 재현되지 않아서, 실사용 중에만 드러나는 버그가 몇 차례 있었습니다.**

- 버전별 변경 이력(무엇을 왜 바꿨고 무엇을 확인했는지)은 [CHANGELOG.md](CHANGELOG.md)에 있습니다. 같은 내용이 GitHub의 각 버전 태그/릴리스 설명에도 올라갑니다.

## 라이선스

이 프로젝트의 라이선스는 아직 정해지지 않았습니다(라이선스 미지정, 모든 권리 보유). 함께 쓰는 외부 소프트웨어(Pillow, img2pdf, pikepdf, PyMuPDF, rarfile, UnRAR 등)는 각자의 라이선스를 따릅니다.
